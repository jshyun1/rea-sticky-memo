# PoC 설계와 제한

`src/NoteStore.cs`는 창과 독립된 저장소입니다. `src/Windows.cs`는 목록 Form과 메모별 Form을 관리하고, `src/Program.cs`가 경로 선택·오류 알림·메시지 루프를 담당합니다. 일반 Windows Forms/.NET Framework API만 사용합니다.

## 데이터와 저장

전용 디렉터리의 `notes.json`에 `Version=1`, `Notes` 배열을 기록합니다. 메모 필드는 UUID 문자열 `Id`, 평문 `Text`, 화면 좌표 `X/Y`, 외곽 크기 `Width/Height`, 0–3의 `Color`, `UpdatedUtc`입니다. 원본의 스키마를 재현한 형식이 아닙니다. 데이터는 암호화하지 않습니다.

시작 시 `app.lock`을 공유 없이 열어 같은 폴더에 대한 두 프로세스의 동시 쓰기를 막습니다. 잠금 파일은 삭제하지 않고 OS 핸들 해제로 소유권을 반환합니다. 잘못된 JSON, 알 수 없는 버전, 중복 UUID, null 본문, 비정상 크기·좌표·색상은 시작 실패로 처리하고 `notes.json`을 덮어쓰지 않습니다.

변경할 상태를 복제한 뒤 같은 폴더에 고유 임시 파일을 만듭니다. 직렬화 → 16 MiB 제한 확인 → `Flush(true)` → `File.Replace` 또는 최초 `File.Move` 순서입니다. 성공한 뒤에만 메모리의 커밋 상태를 교체합니다. 기존 파일 교체 시 `notes.json.bak`에 직전 버전을 보관합니다. 저장 실패 시 기존 커밋 상태를 유지하고 임시 파일 정리를 시도합니다. 파일 시스템 오류로 정리 자체가 실패하면 임시 파일이 남을 수 있습니다.

`File.Replace`는 Windows 공유 위반을 실제로 일으킨 테스트에서 기존 파일과 메모리 상태를 보존했습니다. 정전·디스크 자체 손상·모든 네트워크 파일 시스템에 대한 내구성을 보장한 결과는 아닙니다. 버전 백업은 한 세대이며 매 변경 때 갱신됩니다.

## 창과 자동 저장

메모 ID별로 Form 하나를 유지합니다. X로 메모 창을 닫으면 저장하고 Form만 제거합니다. 목록은 남으며 다시 열 수 있습니다. 재시작 시 저장한 메모 모두를 엽니다. 마지막 메모를 삭제해도 빈 목록은 유지하고 임의의 새 메모를 만들지 않습니다.

텍스트·색상·일반 상태에서의 위치/크기 변경은 450ms debounce 타이머를 다시 시작합니다. 따라서 연속 입력 중에는 저장이 지연될 수 있습니다. Ctrl+S, 메모 닫기, 전체 종료에서 즉시 flush합니다. 저장 실패 시 본문을 유지하고 상태를 표시하며 2초 후 재시도합니다. 창 닫기나 종료 요청은 취소합니다. 전체 종료에서는 모든 창의 flush 성공을 먼저 확인한 후 창을 닫습니다.

삭제는 확인을 받은 뒤 저장소에서 제거하고 타이머를 멈춥니다. 저장 실패 시 창을 유지합니다. 삭제된 창의 이전 debounce 작업이 메모를 되살리지 않게 합니다. 자동 테스트에서 확인 대화상자만 억제하며, 실제 앱에서는 기본값이 '아니요'인 확인창을 사용합니다.

복원할 좌표는 현재 화면 작업 영역으로 보정합니다. DPI/모니터 변경 시 완벽한 물리적 위치 일치는 목표가 아닙니다. 최소 창 크기 240×200, 저장 파일 최대 16 MiB의 PoC 제한이 있습니다. 큰 파일의 전체 재직렬화는 UI를 잠시 멈출 수 있습니다.

## 데이터 보존 범위

기본 경로 `%LOCALAPPDATA%\WithREA\StickyMemoPoC`만 사용하며 Microsoft Sticky Notes 사용자 데이터 경로를 검색하거나 열지 않습니다. 테스트는 제출 폴더 아래 고유 테스트 디렉터리만 사용했습니다. `--data-dir`은 사용자가 명시적으로 지정한 PoC 저장 폴더입니다.

손상 파일의 자동 복구/덮어쓰기는 하지 않습니다. 수동 복구가 필요하면 앱을 종료하고 `notes.json`과 `.bak`을 다른 위치에 먼저 복사한 후 `.bak` 사본을 새 PoC 폴더의 `notes.json`으로 복사하여 `--data-dir`로 여세요. 기존 파일을 그대로 보관한 상태에서 복구 결과를 확인할 수 있습니다.

프로세스 강제 종료 직전의 미저장 debounce 내용은 유실될 수 있습니다. 원본 자동 저장 정책과 동등하다고 주장하지 않습니다. 설치 프로그램, 원본 메모 데이터 호환, 클라우드 동기화, 리치 텍스트 및 이미지 첨부는 구현하지 않았습니다.
